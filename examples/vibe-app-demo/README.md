# Demo: Vibe Notes (synthetic)

**DEMO DATA.** "Vibe Notes" is a synthetic, deliberately weak Next.js-style notes app with AI summaries, the kind of
thing a weekend of vibe coding produces. It is not a real product. Every credential-like string in it is a
deterministic fake generated by `create-app.mjs` at run time, so none is committed to this repository.

## What is here

| Path                                 | What                                                                                                                                                                |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `create-app.mjs`                     | Generates `app/` as its own git repository (baseline commit; `--remediate` adds a fix commit). Fixed author and dates, so commit IDs are the same on every machine. |
| `serve.mjs`                          | A local stand-in deployment on `127.0.0.1:4785` that behaves like the baseline or remediated build (headers, soft 404, exposed `/.env`, auth API).                  |
| `scan-contract.json`                 | HYBRID scan at BETA_PILOT (CT-T2); authorizes passive-http and exposure-probe for the local origin only; maps the app's tests to PC-C-09, PC-S-13 and PC-S-14.      |
| `inputs/observations-*.json`         | Recorded passive observations of the local deployment (timestamps and timings normalized).                                                                          |
| `inputs/test-results-remediated.xml` | JUnit output of the remediated app's real tests (`node --test`) run against the remediated deployment (times and absolute paths normalized).                        |
| `output/baseline/`, `output/retest/` | Committed results, report, blueprint, work packets and dashboard.                                                                                                   |

## Run it offline (reproduces the committed output)

```bash
npm run build                                   # from the repository root
cd examples/vibe-app-demo
node create-app.mjs
node ../../dist/cli/main.js run --contract scan-contract.json --observations inputs/observations-baseline.json --out-dir output/baseline
node create-app.mjs --remediate
node ../../dist/cli/main.js retest --contract scan-contract.json --observations inputs/observations-remediated.json \
  --test-results inputs/test-results-remediated.xml --baseline output/baseline/product-check-results.json --out-dir output/retest
```

Set `SOURCE_DATE_EPOCH=1791972000` (baseline) and `1792058400` (retest) to get byte-identical files.

## Run it live

```bash
node create-app.mjs && node serve.mjs --version baseline &
node ../../dist/cli/main.js run --contract scan-contract.json --allow-network --out-dir /tmp/pc-live
```

The probe sends about ten passive GET requests to `127.0.0.1:4785` (the contract's attestation covers only that
origin). `npm run demo` from the root regenerates everything, including running the app's tests.

## What the story shows

- **Baseline: NOT_READY.** G-SECRETS fails: `/.env` publicly served, a committed live Stripe key and database URL, a
  hard-coded Supabase service-role JWT, privileged keys with `NEXT_PUBLIC_` prefixes, and the OpenAI SDK used in a
  client component. Authorization and isolation are UNVERIFIED (no executed tests yet), not passed.
- **Retest: READY_WITH_CONDITIONS.** 35 findings verified fixed by new evidence, gates pass with the app's executed
  authorization and isolation tests, two P2s remain (no error monitoring, no AI evaluation suite). HTTPS is NOT_TESTED
  because the demo runs on a loopback origin.
